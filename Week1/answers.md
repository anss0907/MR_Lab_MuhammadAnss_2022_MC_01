# Post-Lab Questions — Week 1

## 1. Define: node, topic, package, workspace (one sentence each)

- **Node**: A node is a single process in ROS 2 that performs a specific computation, such as reading a sensor or controlling a motor.
- **Topic**: A topic is a named communication channel through which nodes can publish and subscribe to messages asynchronously.
- **Package**: A package is an organizational unit in ROS 2 that contains code, configuration, and build information for a specific functionality.
- **Workspace**: A workspace is a directory that contains one or more ROS 2 packages along with the build, install, and log outputs generated by `colcon build`.

## 2. Why is sourcing required? What happens if you do not source a workspace?

Sourcing sets the necessary environment variables (such as `ROS_DISTRO`, `AMENT_PREFIX_PATH`, `PYTHONPATH`) so that the terminal knows where to find ROS 2 tools and your custom packages. If you do not source the workspace, commands like `ros2 run` and `ros2 pkg list` will not be able to locate your packages or may not work at all (`command not found`).

## 3. What is the purpose of `colcon build`? What folders does it generate?

`colcon build` compiles and installs all the packages in the workspace's `src/` directory. It generates three folders:
- **build/**: Intermediate build artifacts and compiled files.
- **install/**: The installed packages and executables, ready to be sourced and used.
- **log/**: Build logs containing output and error messages from the build process.

## 4. In your own words, explain what the `entry_points` console script does in `setup.py`.

The `entry_points` section in `setup.py` maps a command-line executable name to a specific Python function. For example, `'simple_node = my_first_pkg.simple_node:main'` tells ROS 2 that when you run `ros2 run my_first_pkg simple_node`, it should call the `main()` function inside the `simple_node.py` file of the `my_first_pkg` module. Without this mapping, ROS 2 would not know which function to execute.
